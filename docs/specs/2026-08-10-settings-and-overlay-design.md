# 설정창과 오버레이 개편 — 설계 문서

작성 2026-08-10. 기준 커밋 `d8707f3`. 검토 반영 2026-08-11.

기존 설계 문서(`2026-08-10-claude-usage-overlay-design.md`)를 대체하지 않는다.
그 위에 얹는 변경만 적는다.

## 1. 목적

메모장으로 `config.json`을 고치던 것을 GUI로 바꾸고, 그 김에 오버레이를
평소에 덜 거슬리게 만든다. 다섯 덩어리다.

1. **설정창** — 트레이 메뉴 "설정 파일 열기"를 대체한다
2. **오버레이 개편** — 기본을 66×66 정사각형으로 줄이고, 지금 모습은 "자세히 보기"로 옮긴다
3. **클릭 전환** — 링 안 숫자를 사용량 ↔ 남은 시간으로 바꾼다
4. **트레이 아이콘 고정** — 작업 표시줄에 붙여두는 것을 프로그램이 돕는다
5. **글꼴 번들** — Pretendard를 exe에 넣어 다운로드·설치 개념을 없앤다

## 2. 실측으로 확인한 것

설계의 근거다. 전부 이 PC(Windows 11 26200, 배율 100%, 앱 테마 밝음)에서 쟀다.

### 2.1 어두운 제목 표시줄은 된다

`DwmSetWindowAttribute(hwnd, 20, TRUE)`가 `rc=0`을 돌려주고, 대조군 창과
나란히 띄워 육안으로 확인했다. **네이티브 창을 그대로 쓰면서 제목 표시줄만
어둡게 할 수 있다** — 창 이동·Alt+Tab·스냅·작업 표시줄이 전부 정상으로 남는다.

무테두리로 직접 그릴 필요가 없다. `winmetrics.round_window_corners()`가 이미
같은 API를 쓰고 있으므로 함수 하나가 늘 뿐이다.

### 2.2 트레이 아이콘 고정은 즉시 반영된다

> **정정 (2026-08-13).** 이 절은 원래 "즉시 반영되지 않는다 · 다음 로그온부터"로
> 적혀 있었고 **그 결론은 틀렸다.** 아래 실패 표는 Claude Code(MSIX 패키지 앱)의
> 셸에서 띄운 인스턴스로 잰 것인데, 패키지 컨테이너 안에서는 `HKCU` 쓰기가 패키지
> 전용 하이브(`...\Packages\Claude_*\SystemAppData\Helium\User.dat`)로 재지정되어
> **탐색기가 그 값을 볼 수 없다.** `%APPDATA%`도 같은 이유로 재지정되므로 그때는
> `config.json` 저장도 딴 곳에 쓰인다.
>
> 컨테이너 밖(사용자가 직접 띄운 인스턴스, 재부팅 뒤 자동 실행)에서는 예외 없이
> 즉시 반영된다 — 켜면 아이콘이 작업 표시줄로 나오고 끄면 ∧ 안으로 들어간다.
> 이 프로그램의 동작은 **컨테이너 밖에서 띄운 인스턴스로 재야 한다.**

Windows 11은 아이콘 표시 여부를 `HKCU\Control Panel\NotifyIconSettings\<해시>`의
`IsPromoted` DWORD에 담는다. 값을 쓰면 탐색기가 곧바로 따라온다. 로그오프도
탐색기 재시작도 필요 없다.

**탐색기 재시작은 하지 않는다** — 사용자의 열린 창을 전부 건드리는 짓이고,
그럴 이유도 없다.

아래는 정정 전에 남긴 표다. 셋 다 컨테이너 안에서 잰 것이라 무효다.

| 시도 | 그때의 관측 |
|---|---|
| `IsPromoted=1` 쓰기 | 작업 표시줄에 안 나타남 |
| 값을 쓴 뒤 아이콘 재등록(앱 재시작) | 안 나타남 |
| `WM_SETTINGCHANGE` 7종 브로드캐스트 | 안 나타남 |

### 2.3 Windows 10은 아이콘별 고정을 하지 않는다

Win10은 `HKCU\Software\Classes\Local Settings\...\TrayNotify`의 `IconStreams`
이진 blob에 담는다. 형식이 문서화돼 있지 않고 OS 버전마다 바뀔 수 있어
건드리지 않는다. 전역 스위치(`EnableAutoTray=0`)는 있지만 모든 앱에 적용되므로
우리가 조용히 켤 값이 아니다.

드래그로 꺼내는 것은 Win10에도 있고, **Win10에만 있는 아이콘별 설정 화면**
(설정 > 작업 표시줄 > 작업 표시줄에 표시할 아이콘 선택)도 있다. 안내는 그쪽을 가리킨다.

### 2.4 GDI는 글꼴 파일을 잠그지 않는다

`AddFontResourceW`로 올린 채 파일을 지웠고 성공했다. 폴더 통째 삭제도 됐다.
**PyInstaller 단일 파일 exe가 종료할 때 임시 폴더를 지우는 동작이 그대로
성공한다** — 종료 시 `RemoveFontResourceW`를 부를 필요가 없고 찌꺼기도 안 남는다.

Pretendard TTF 둘은 5.1MB, 현재 exe는 18.5MB다. 라이선스는 SIL OFL 1.1이고
"any software와 함께 번들·재배포할 수 있다"고 명시돼 있다. 조건은 저작권 표시와
라이선스 파일 동봉뿐이며 우리는 글꼴을 고치지 않는다.

### 2.5 링 안에 들어가는 글자 크기

3.1절의 링 치수에서 안쪽 지름은 40px이 나온다. 링 선과 글자 사이 4px을 남기면
쓸 수 있는 폭은 32px이다. Pretendard와 폴백(Segoe UI) 중 넓은 쪽으로 쟀다.

| 문구 | 들어가는 최대 크기 |
|---|---|
| `62` | 25px |
| `100` | 18px |
| `5:20` | 15px |

같은 크기로 `100`과 `5:20`을 둘 다 담으려면 15px이다. 그러면 평소 보는 숫자가
작아지므로 **문구마다 시작 크기를 따로 고른다.**

**단 이 값을 상수로 확정하지 않는다.** 배율 100%에서 여유가 정확히 0px이라
반올림이 한 번만 어긋나면 넘친다. 배율별 실측:

| 배율 | 가용폭 | `100` | `5:20` |
|---|---|---|---|
| 100% | 32px | 18px → 32px | 15px → 32px |
| 125% | 40px | 22px → 40px | 19px → **42px 넘침** |
| 150% | 48px | 27px → **49px 넘침** | 22px → 48px |

그래서 위 표는 **시작값**으로만 쓰고, 실제 크기는 `overlay._pct_font()`가 지금
하는 대로 **들어갈 때까지 1px씩 줄여서** 정한다. 이 루프 하나가 배율뿐 아니라
3.3절의 두 자리 시(`10:14`)까지 함께 흡수한다. `create_text`는 넘쳐도 경고 없이
자르므로 상수로 박아두면 깨진 화면을 아무도 못 본다.

### 2.6 숫자의 세로 위치는 정확한 중앙이 없다

18px 숫자의 잉크는 13px(홀수), 링 안쪽은 40px(짝수, 2.5절)이다.
화면을 캡처해 픽셀을 센 결과:

| `create_text`의 y | 잉크 범위 | 위 여백 | 아래 여백 |
|---|---|---|---|
| 32 | 26~38 | 13 | 14 |
| 33 | 27~39 | 14 | 13 |

**반 픽셀은 위쪽으로 보낸다.** 아래로 보내면 처져 보인다(육안 확인).

이 값을 상수로 박지 않는다. 배율이 125%·150%가 되면 홀짝이 달라져 다시
틀어진다. **그릴 때마다 잉크 상자를 재서 중앙을 맞추고 남는 반 픽셀을 위로
보낸다.**

**`icon_render._centered_text`를 그대로 베끼면 안 된다.** 잉크 상자를 매번
재는 것은 맞지만 좌표를 `round()`로 맞추고 있고, 파이썬의 `round()`는 은행가
반올림이라 절반은 아래로 간다 — `round(1.5)=2`(아래), `round(2.5)=2`(위),
`round(0.5)=0`(위). 값의 홀짝에 따라 방향이 갈리므로 "위로"가 지켜지지 않는다.
`text_center.py`는 `floor`로 명시해야 하고, 그래야 12장의 정렬 테스트가 선다.

`icon_render`도 같은 규칙을 따르게 하려면 같은 수정이 필요하지만, 16px 아이콘에서
1px 차이라 이번 범위에서는 건드리지 않는다.

### 2.7 색 대비

트레이 아이콘은 채움 위에 흰 숫자를 얹는다. 고른 색을 그대로 쓰면 노란 구간이
읽히지 않는다.

| | 견본 그대로 | 어둡게 한 뒤 |
|---|---|---|
| 초록 | 2.61:1 | 3.19:1 |
| 노랑 | **1.71:1** | 2.69:1 |
| 빨강 | 3.35:1 | 4.12:1 |

1.71:1은 기존 `theme.py` 주석이 "사실상 읽히지 않는다"고 적어둔 구간이다.
트레이에 세 팔레트를 동시에 띄워 비교한 뒤 어두운 쪽으로 정했다.

**hex 값은 7장에 모아 두었다.** 여기는 대비 수치만 남긴다.

### 2.8 레지스트리 항목에서 우리 것을 고르는 법

`NotifyIconSettings` 하위 51개 항목을 전부 읽어 확인했다.

**`ExecutablePath`는 절대 경로가 아니다.** 시스템 폴더 아래 실행 파일은
KNOWNFOLDERID GUID 접두사로 저장된다.

```
{6D809377-6AF0-444B-8957-A3773F02200E}\PowerToys\PowerToys.exe   ← C:\Program Files
{7C5A40EF-A0FB-4BFC-874A-C0F2E0B9FA8E}\Steam\steam.exe           ← C:\Program Files (x86)
{F38BF404-1D43-42F2-9305-67DE0B28FC23}\explorer.exe              ← C:\Windows
C:\Users\<계정>\...\dist\ClaudeUsageOverlay.exe                   ← 사용자 프로필은 평문
```

윈도우를 다른 드라이브에 깔아도 항목이 안 깨지게 하려는 것이다. 지금은 exe가
사용자 프로필 아래라 평문이지만, **설치 프로그램이 없으므로 사용자가 exe를
`C:\Program Files\`에 두는 순간 `sys.executable`과의 문자열 비교가 어긋난다.**
`SHGetKnownFolderPath`로 풀 수는 있고 위 셋 다 실제로 풀렸지만, 아이콘 고정은
실패해도 조용히 넘어가는 기능이라 그만한 정확도가 필요하지 않다.

**`InitialTooltip`에는 툴팁이 줄바꿈까지 그대로 들어 있다.** 우리 항목은
`Claude 사용량\n불러오는 중`이었고, 51개 중 이것으로 시작하는 것은 우리뿐이다.
Claude 데스크톱 앱 항목은 툴팁이 비어 있어 겹치지 않는다.

**같은 실행 파일에 항목이 여럿 생긴다.** 실측: `vgtray.exe` 4개, `explorer.exe`
5개, `Overwolf.exe` 2개(툴팁만 다름). 우리 것도 이미 3개다 — `python.exe`,
`pythonw.exe`, `dist\ClaudeUsageOverlay.exe`.

그래서 5장의 찾는 법은 **툴팁을 주 조건으로 두고, 경로는 후보를 가리는 데만
쓰며, 맞는 항목이 여럿이면 전부에 쓴다.**

## 3. 오버레이

### 3.1 기본 모드 — 66 × 66

정사각형. 링 바깥 지름 50px(여백 8px), 두께 5px. **링 안에 숫자 하나만.**

- 사용량은 18px 굵게. `100`이면 그대로 18px(2.5절 표)
- 값이 없는 상태는 기호 하나만 — `icon_render`의 어휘를 그대로 쓴다
  - `!` 빨강 — 재로그인 필요
  - `?` 흰색 — 데이터 형식이 바뀜
  - `…` 흐린 회색 — 아직 값 없음
- **갱신이 늦어지면 링 채움을 지우고 흐린 `!` 하나만 그린다.** 낡은 숫자는
  없느니만 못하고, 숫자를 못 믿으면 링도 못 믿는다. **자세히 모드도 같다**(3.2절)
- 값이 낡았지만 아직 주기 안이면 지금처럼 통째로 45% 흐리게

기준은 `poll_seconds × 2 + 60초`다. **한 주기를 통째로 건너뛰어야 지운다.**
한 번의 실패로 지우면 안 된다 — `poller._handle_unauthorized()`의 401 경합은
백오프 없이 다음 틱에 저절로 낫는데, `poll_seconds + 60`이면 그 회복을 기다리는
동안(기본 5분 주기에서 4분) 내내 숫자가 사라진다. 60초는 분 반올림 경계에서
깜빡이지 않게 더한다.

`!`가 두 뜻을 갖게 되지만 밝기로 갈린다 — **기다리면 낫는 것은 흐리게, 사용자가
조치해야 하는 것은 또렷하게.** `icon_render`가 이미 쓰는 규칙이다.

갱신이 늦어지는 원인은 `poller.py`가 정한다. `credentials.py`가 토큰을 스스로
갱신하게 됐어도(커밋 `150ff57`) 이 목록은 그대로다 — 갱신에 실패해도 살아 있는
토큰이 있으면 조용히 그걸로 버티므로, 화면까지 오는 것은 네트워크 오류(백오프
최대 30분) · 429 · 401 경합 셋이다. 새 기준에서는 **401 경합이 한 번 나는
것으로는 지워지지 않는다** — 두 번 연속 실패해야 한다. 세 번이면 그건 경합이
아니라 인증 문제라 `Status.RELOGIN`으로 넘어가 또렷한 `!`가 된다.

### 3.2 자세히 보기 모드 — 190 × 62

지금 모습에서 하나만 다르다. 링 + 카운트다운 + 갱신 문구 두 줄은 그대로고,
창 폭 190px의 근거(가장 긴 문구 181px + 여유 9px)도 그대로 살아 있다 —
**이제 그것은 자세히 모드 전용 근거다.**

다른 하나는 **갱신이 늦어졌을 때다. 여기서도 링 채움과 숫자를 지우고 흐린
`!`를 그린다.** 3.1절의 근거("낡은 숫자는 없느니만 못하다")는 창 크기와 무관해서,
한쪽만 지우면 클릭 한 번으로 못 믿을 숫자가 도로 나타난다. 아래 두 줄은 지금처럼
흐리게 그대로 둔다 — `N분째 갱신 실패`가 바로 옆에서 상태를 말하고 있으므로
카운트다운까지 지울 이유는 없다.

### 3.3 조작

| | 기본 | 자세히 |
|---|---|---|
| 마우스 올림 | 변화 없음 | 우상단에 ⚙·✕ |
| 왼쪽 클릭 | 사용량 ↔ 남은 시간 | 아무 일 없음 |
| 드래그 | 이동 | 이동 |
| 오른쪽 클릭 | 메뉴 | 메뉴 |

- 단추는 **자리가 있는 쪽에만** 둔다. 66px 창의 구석에 넣으면 12px도 안 되어 못 누른다
- 자세히 모드의 **⚙는 설정창을 열고, ✕는 오버레이를 숨긴다.** ✕는 프로그램을
  끄지 않는다 — 트레이는 그대로 살아 있고 되돌리는 길은 트레이 메뉴다.
  풍선 알림도 띄우지 않는다. 우클릭 메뉴의 `설정…`·`오버레이 숨기기`와 같은
  동작이므로 단추는 지름길일 뿐이다
- 숨기기는 **누르는 즉시** 적용되고 `overlay_visible`도 그때 저장된다. 설정창의
  일괄 적용과 다른 이유는, 단추는 폼이 아니라 그 자체가 동작이기 때문이다
- 우클릭 메뉴는 양쪽 같다: `설정… / 자세히 보기 / ─ / 오버레이 숨기기`.
  가운데 항목은 **문구가 바뀌는 토글**이라 자세히 모드에서는 `기본 보기`가 된다.
  트레이의 `오버레이 보이기 / 숨기기`와 같은 방식이므로 체크 표시를 쓰지 않는다
- **드래그와 클릭은 3px로 가른다.** 누른 자리에서 3px 이상 움직이면 이동,
  그 안에서 떼면 클릭
- 자세히 모드에 좌클릭 전환이 없는 이유는 아래 줄에 이미 카운트다운이 있어서다
- **전환 상태는 저장하지 않는다.** 창 위치를 저장하지 않는 것과 같은 이유이고,
  다시 켜면 사용량으로 돌아온다

남은 시간 표기는 `5:20`(시:분)이다. 자리를 채우는 `0`은 붙이지 않는다.
`resets_at`이 없으면 전환해도 `—`가 나온다.

**시가 한 자리라고 가정하지 않는다.** 5시간 창이니 그럴 것 같지만,
`tests/test_overlay_layout.py`는 `format_countdown`의 최장을 `"10시간 14분 후 리셋"`
으로 잡고 있어 코드는 두 자리를 허용한다. `10:14`는 15px에서 38~40px이라 32px 안에
못 들어간다(실측). 2.5절의 줄이는 루프가 이것까지 흡수하므로 표기 규칙을 따로 두지
않는다 — 두 자리가 오면 글자가 작아질 뿐 잘리지 않는다.

### 3.4 모드를 바꿀 때의 창 위치

창 크기가 바뀌므로 **오른쪽 아래 모서리를 고정**하고 크기를 바꾼다. 기본 위치가
작업 영역 오른쪽 아래이므로 그래야 제자리에 남는다.

**지금 코드에는 이런 보정이 없다.** 창 크기가 기동할 때 한 번 정해지고 그 뒤로
바뀌지 않기 때문이다. 예전에 `16d1eba`가 폭 변경에 대해 같은 보정(`_keep_right_edge`)을
넣은 적은 있으나, 위치 저장 기능을 통째로 되돌린 `62a2fa4`가 함께 지웠다.
새로 만드는 부분이다.

**옮겨둔 자리에서는 작업 영역 안으로 되민다.** 창은 드래그로 어디든 갈 수 있고,
왼쪽 끝에 붙여둔 상태에서 자세히로 바꾸면 오른쪽 아래를 고정한 채 왼쪽으로 124px
자라 화면 밖으로 나간다. 새 좌표를 `work_area()` 안으로 클램프한다.

## 4. 설정창

네이티브 `Toplevel`. 크기 조절은 막는다. 대략 300 × 430.

**이 치수는 배율 100% 기준값이다.** 오버레이가 모든 픽셀에 `dpi_scale()`을 곱하는
것과 똑같이(overlay.py 머리말) 창 크기·여백·위젯 치수에 전부 곱한다. 글꼴은 음수
픽셀로 준다 — 포인트로 주면 `tk scaling`이 이미 반영한 배율에 한 번 더 곱해져
150%에서 글자만 창을 넘는다. 오버레이가 겪은 그대로다.

제목 표시줄은 2.1절의 DWM 속성으로 어둡게 한다. 실패하면 제목 표시줄만
밝은 채로 뜬다 — 보기 나쁠 뿐 동작에는 지장이 없다.

### 4.1 담기는 것

```
☑ 오버레이 표시
    ☐ 자세히 보기
☑ 시작할 때 자동 실행
☐ 작업 표시줄에 트레이 아이콘 고정
    끄면 ∧ 안(숨은 아이콘)으로 들어갑니다.
────────────────────────
조회 주기   [ 5분 ▾ ]        2 · 5 · 10 · 30분
노란색으로 바뀌는 사용률  ──●────  70%     50~100, 5단위
빨간색으로 바뀌는 사용률  ──────●  90%     50~100, 5단위
────────────────────────
닫으면 적용됩니다                    [ 닫기 ]
```

- **"자세히 보기"는 "오버레이 표시"의 하위 항목**이라 들여쓰고, 표시를 끄면 같이 흐려진다
- **조회 주기는 드롭다운**이다. 2분이 하한이고 그 아래는 호출 한도에 걸린다
  (`MIN_POLL_SECONDS`). 파일에 손으로 240초를 적어둔 경우 가장 가까운 5분이
  선택된 채로 열리고, 닫으면 그 값이 저장된다 — 드롭다운으로 바꾼 이상 피할 수 없다
- **슬라이더는 5단위**다. 세밀함보다 손으로 맞추기 쉬운 쪽을 골랐다.
  노란은 빨간보다 5%p 아래에서 멈추고 반대도 같다 — **서로 밀어내지 않고 그 자리에 선다.**
  같은 규칙으로 보정하는 자리는 **설정창이 아니라 `load_config()`다.** 옛 파일에
  `warn ≥ danger`가 들어 있으면 노란색이 영영 안 나오는데, 설정창에서만 보정하면
  창을 한 번도 안 연 사람은 그대로 남는다. `poll_seconds`의 하한을 거는 것과 같은 자리다
- 트레이 고정 체크박스는 **Windows 10에서 비활성**이고 안내 문구가 바뀐다

### 4.2 직접 그리는 위젯

ttk 기본 위젯은 윈도우 기본 테마에서 색이 먹지 않는다. 체크박스·슬라이더·
드롭다운 셋을 캔버스에 직접 그린다. 링과 트레이 아이콘을 이미 PIL로 그리고
있으므로 이 코드베이스에 낯선 방식은 아니다.

- **체크박스** — 모서리를 둥글게 깎은 사각형. 꺼짐은 테두리만, 켜짐은 `GREEN`
  채움(7장)에 어두운 체크. **체크 표시는 글꼴 글리프(`✓`)가 아니라 끝이 둥근
  두꺼운 선 둘로 긋는다.** 글리프를 쓰면 글꼴마다 모양이 달라지고 획이 가늘다.
  캔버스 `create_line`의 `capstyle="round"`·`joinstyle="round"`로 그린다
- **슬라이더** — 손잡이는 원. 채운 부분은 그 기준의 색(`YELLOW`·`RED`)으로,
  빈 부분은 어두운 회색으로 칠한다. 무엇을 정하는 값인지 글자를 안 읽어도 보인다
- **드롭다운** — 펼친 목록의 **바깥 테두리를 단추의 바깥 테두리와 맞춘다.**
  폭을 따로 적지 않고 좌우를 테두리 두께만큼 물려서, 항목 글자가 길어져도 어긋나지 않는다

### 4.3 언제 적용되나

**닫을 때 한 번에.** 닫기 단추·제목줄 ✕·Esc가 모두 같은 일을 하고 취소는 없다.
값들이 다시 고르면 그만인 것들이라 취소가 벌어줄 게 없고, ✕만 취소로 두면
실수로 통째로 잃는다.

적용은 공유 `Config` 객체를 고치는 것으로 끝난다. 폴러·오버레이·트레이가
매 틱 다시 읽으므로 재시작 안내가 필요 없다.

- 색 기준 → 다음 다시 그리기(1초 이내)
- 조회 주기 → **다음 폴링 틱부터.** 자고 있는 대기를 깨우지 않는다. 깨우면
  API를 한 번 더 부르게 되고 그게 429의 원인이다
- 자동 실행·아이콘 고정 → **닫을 때 레지스트리에 쓴다.** 체크하는 순간이 아니다.
  **`Config`에는 저장하지 않는다** — 진짜 상태가 레지스트리에 있으므로, 창을 열 때
  거기서 읽어 체크박스를 그린다

### 4.4 함정 — 설정창을 열어둔 채 밖에서 값을 바꾸면

설정창이 떠 있는 동안 오버레이 우클릭 메뉴나 트레이로 표시를 끄면, 설정창의
체크박스는 켜진 옛 값 그대로다. 닫는 순간 그 값이 덮어써서 **오버레이가 도로
나타난다.**

**`overlay_detailed`도 똑같다.** 3.3절의 우클릭 `자세히 보기`가 밖에서 바꾸는
두 번째 값이고 9장에 따라 저장되는 값이다. 설정창을 열어둔 채 우클릭으로 자세히를
켜면 닫는 순간 되돌아간다.

밖에서 바뀌는 값은 이 둘뿐이다 — 자동 실행과 아이콘 고정은 `Config`에 없고
레지스트리가 진짜 상태다(4.3절). **둘 다, 밖에서 바뀌면 열려 있는 설정창의
체크박스를 따라 갱신한다.**

### 4.5 스레드

설정창은 두 곳에서 열린다 — 오버레이 우클릭(메인 스레드)과 트레이 메뉴(pystray
스레드). tkinter 창 조작은 메인 스레드 몫이므로 트레이 쪽은 위젯의 `after(0, ...)`로
넘긴다 — `overlay.py:194`의 `self._win.after(0, ...)`가 같은 방식이다. 이미 열려
있으면 새로 만들지 않고 앞으로 끌어온다.

## 5. 트레이 아이콘 고정

Windows 11에서만 동작한다.

- **찾는 법** — `NotifyIconSettings` 하위 키를 훑어 **`InitialTooltip`이
  "Claude 사용량"으로 시작하는 것을 고른다.** `ExecutablePath`도 같이 보되
  **필수 조건으로 쓰지 않는다** — 2.8절에서 봤듯 그 값은 절대 경로가 아닐 수 있고,
  어긋나면 기능이 아무 표시 없이 죽는다. 경로는 후보가 여럿일 때 실행 파일 이름으로
  가리는 데만 쓴다
- **맞는 항목이 여럿이면 전부에 쓴다** — 같은 실행 파일에 항목이 여러 개 생기는
  것을 실측했다(2.8절). 소스로 돌리다 exe로 옮기면 우리 것도 여러 개가 된다
- **시점** — 항목은 아이콘이 한 번 뜬 뒤에야 탐색기가 만든다. 첫 실행 자동
  시도는 별도 스레드에서 잠깐 기다렸다 쓰고, 끝내 못 찾으면 조용히 포기한다
- **첫 실행 1회 자동** — `config.json`이 없으면 한 번 써둔다. 이후로는 건드리지
  않는다. 나중에 직접 숨긴 사람과 싸우지 않기 위해서다
- **설정창 체크박스** — 언제든 켜고 끈다. 쓰고 나서 레지스트리를 다시 읽어
  실제 상태로 그린다. 안 그러면 화면이 거짓말을 한다
- 키가 없는 환경(Win10 등)에서는 체크박스가 비활성이고 아무것도 쓰지 않는다

## 6. 첫 실행

> **정정 (2026-08-13).** 이 절은 원래 **첫 실행 안내창**을 정의했고, 그 창은
> 없앴다. 존재 이유가 "프로그램이 아이콘을 꺼내줄 수 없으니 사용자가 직접
> 꺼내라"였는데, 2.2절의 정정대로 프로그램이 즉시 꺼낼 수 있다. 사용자가 할 일이
> 없으므로 알릴 것도 없다. 도식·OS별 마지막 줄도 함께 사라졌다.

`config.json`이 없으면 첫 실행이다. 그때 하는 일은 둘뿐이다.

1. **`config.json`을 기본값으로 저장한다** — 첫 실행 표시를 남기는 것이 목적이다.
   이게 없으면 아래 자동 고정이 매 기동마다 돈다
2. **트레이 아이콘 고정을 한 번 켠다** (5장)

**첫 실행인지는 `config.json`을 만들기 전에 판정한다.** 순서가 뒤집히면 판정이
늘 "첫 실행 아님"이 되어 자동 고정이 영영 돌지 않는다.

## 8. 글꼴 번들

TTF 둘과 `OFL.txt`를 `claude_usage_overlay/fonts/`에 넣고 exe에 함께 묶는다.
기동할 때 그 경로로 `AddFontResourceW`를 부른다.

- **첫 실행부터 Pretendard다.** 기다림 0초, 네트워크 0, 실패 경로 0
- 계정 글꼴 폴더에도 레지스트리에도 쓰지 않는다
- 소스로 돌릴 때는 패키지 폴더, exe로 돌릴 때는 `sys._MEIPASS` 아래를 본다
- 번들 로드가 실패해도 `pick_font_family`가 Segoe UI로 떨어뜨린다

**사라지는 것** — `fetch_zip` · `pick_zip_asset` · `wanted_members` ·
`extract_to` · `register` · `install` · `is_installed`, 트레이 메뉴의
"Pretendard 글꼴 설치", README의 **설치** 안내. `font_install.py`는 40줄쯤으로
줄고 `activate()`만 남는다.

exe는 2.4절의 크기에서 3MB 안팎 커진다.

### 8.1 이미 깔아둔 사람

트레이 메뉴로 설치했던 사용자에게는 계정 글꼴 폴더에 TTF 둘(5.1MB)과
`HKCU\Software\Microsoft\Windows NT\CurrentVersion\Fonts`의 값 둘이 남는다.
번들을 쓰기 시작하면 아무도 안 보는 찌꺼기가 된다.

**우리가 지우지는 않는다.** 값 이름도 파일 경로도 사용자가 손으로 설치한 것과
구별되지 않아서, 지우면 다른 용도로 Pretendard를 쓰던 사람의 글꼴을 뺏는다.
같은 이름이 두 벌 올라오는 것은 무해하다 — `pick_font_family`는 이름만 보고,
GDI는 중복 등록을 참조 계수로 다룬다.

**대신 README의 삭제 안내는 남긴다.** 설치 안내만 지운다. 둘 다 지우면 잔여물은
생기는데 치우는 방법을 아는 사람이 없어진다.

## 9. 트레이 메뉴와 config

```
오버레이 보이기 / 숨기기
지금 갱신
──────────────
설정…
시작할 때 자동 실행          ☑
──────────────
종료
```

"설정 파일 열기"는 설정창이 대신하므로 뺀다. "Pretendard 글꼴 설치"는 8장으로
사라진다. 자동 실행이 트레이와 설정창 양쪽에 있지만 둘 다 레지스트리를 읽어
그리므로 어긋나지 않는다.

`config.py`는 **`UI_OWNED` 개념이 없어진다.** 그 근거는 "나머지는 사용자가
메모장으로 고치는 값"이었는데, 이제 전부 GUI가 소유하므로 저장은 전체 쓰기로
단순해진다. 남는 위험은 프로그램이 켜진 채 파일을 손으로 고치는 경우뿐이고,
이제 그럴 이유가 없다.

새 필드는 `overlay_detailed: bool = False` 하나다. 기본값이 `false`인 쪽이
기본 모드와 일치해서 파일을 열어본 사람이 헷갈리지 않는다.

## 10. 모듈 구조

판단은 순수 함수로 빼고 UI는 얇게 — `ring_render` · `icon_render`가 이미
쓰는 방식을 따른다.

| 파일 | 역할 |
|---|---|
| `slider.py` (신규) | 캔버스 슬라이더(4.2절). 값↔픽셀·클램프·5단위 스냅은 순수 함수 |
| `dropdown.py` (신규) | 캔버스 드롭다운(4.2절) |
| `checkbox.py` (신규) | 캔버스 체크박스(4.2절) |
| `settings_window.py` (신규) | 설정창 `Toplevel`. 초안을 들고 있다가 닫을 때 `Config`에 커밋 |
| `tray_promote.py` (신규) | `NotifyIconSettings` 항목 찾기·읽기·쓰기. 못 하면 조용히 `False` |
| `first_run.py` (신규) | 첫 실행 판정 (안내창은 6장 정정으로 사라졌다) |
| `text_center.py` (신규) | 잉크 상자를 재서 중앙에 놓는 좌표 계산. 링 안 숫자와 슬라이더 값 표시가 함께 쓴다 |
| `overlay.py` | 두 모드, 클릭 전환, 우클릭 메뉴, 3px 판정 |
| `theme.py` | 7장의 색 |
| `config.py` | `UI_OWNED` 제거, `overlay_detailed` 추가 |
| `tray.py` | 메뉴 개편 |
| `font_install.py` | 번들 로드만 남김 |
| `__main__.py` | 첫 실행 판정, 아이콘 고정 시도 |
| `build.py` | 글꼴 `--add-data` 추가 |

**`.spec`이 아니다.** `build.py`는 `--onefile` 등 인자를 직접 넘겨 PyInstaller를
부르므로 `ClaudeUsageOverlay.spec`은 **아무도 읽지 않는 빌드 부산물**이다. 거기에
`datas`를 넣어도 빌드에 반영되지 않는다. 그 파일에는 만든 PC의 절대 경로
(`C:/Users/<계정>/IdeaProjects/...`)가 박혀 있어 다른 PC에서는 쓸 수도 없다.

저장소에는 원래 없다 — `.gitignore`의 `*.spec`이 이미 걸러내고 있고, 빌드할 때마다
로컬에 새로 생긴다. **그러니 지울 것은 없고, 대신 그 파일을 정본으로 착각하지
않으면 된다.** 글꼴을 넣는 자리는 `build.py`의 인자 목록 한 곳뿐이다.

## 12. 테스트

창을 띄우지 않고 재는 것들이다.

- 슬라이더 기하 — 값↔픽셀 왕복, 범위 밖 클램프, 5단위 스냅
- 노란·빨간이 서로를 넘지 않는 규칙, 불러올 때의 보정
- 초안 → `Config` 커밋 (순수 함수로 빼서)
- 조회 주기 드롭다운 — 목록에 없는 값(240초)이 가장 가까운 항목으로 붙는지
- **링 안 문구가 링 안에 들어가는지** — `62` · `100` · `5:20` · `0:27` · `10:14`,
  **배율 1.0 · 1.25 · 1.5** 각각에서, Pretendard와 폴백 둘 다로 재서 넓은 쪽.
  줄이는 루프를 거친 뒤의 크기를 잰다. 2.5절 표가 근거다
- **갱신 지연 임계** — `poll_seconds × 2 + 60`을 경계로, 한 번의 실패는 숫자를
  남기고 두 번 연속 실패는 지우는지 (3.1절)
- **잉크 중앙 정렬** — 배율 1.0 · 1.25 · 1.5에서 위·아래 여백 차이가 1px 이하이고
  남는 반 픽셀이 위로 가는지
- 3px 판정 — 2px 이동은 클릭, 4px 이동은 드래그
- 레지스트리 **항목 목록에서 우리 것 고르기** — 실제 접근은 얇은 껍데기로 분리.
  `python.exe` 경로가 겹치는 경우, `ExecutablePath`가 GUID 접두사로 저장된 경우,
  우리 것이 여러 개인 경우가 여기 들어간다(2.8절)
- 기존 `test_config.py`의 `UI_OWNED` 관련 테스트 갱신
- 기존 `test_font_install.py`는 다운로드·압축 해제 판정이 통째로 사라지므로 함께
  정리한다. `activate()` 몫만 남긴다
- 기존 `test_overlay_layout.py`는 자세히 모드 근거로 남기고, 기본 모드 몫을 추가
