# 설정창과 오버레이 개편 — 설계 문서

작성 2026-08-10. 기준 커밋 `d8707f3`.

기존 설계 문서(`2026-08-10-claude-usage-overlay-design.md`)를 대체하지 않는다.
그 위에 얹는 변경만 적는다.

## 1. 목적

메모장으로 `config.json`을 고치던 것을 GUI로 바꾸고, 그 김에 오버레이를
평소에 덜 거슬리게 만든다. 다섯 덩어리다.

1. **설정창** — 트레이 메뉴 "설정 파일 열기"를 대체한다
2. **오버레이 개편** — 기본을 66×66 정사각형으로 줄이고, 지금 모습은 "자세히 보기"로 옮긴다
3. **클릭 전환** — 링 안 숫자를 사용량 ↔ 남은 시간으로 바꾼다
4. **트레이 아이콘 고정** — 작업 표시줄에 붙여두는 것을 프로그램이 돕는다
5. **글꼴 번들** — Pretendard를 exe에 넣어 다운로드·설치 개념을 없앤다

## 2. 실측으로 확인한 것

설계의 근거다. 전부 이 PC(Windows 11 26200, 배율 100%, 앱 테마 밝음)에서 쟀다.

### 2.1 어두운 제목 표시줄은 된다

`DwmSetWindowAttribute(hwnd, 20, TRUE)`가 `rc=0`을 돌려주고, 대조군 창과
나란히 띄워 육안으로 확인했다. **네이티브 창을 그대로 쓰면서 제목 표시줄만
어둡게 할 수 있다** — 창 이동·Alt+Tab·스냅·작업 표시줄이 전부 정상으로 남는다.

무테두리로 직접 그릴 필요가 없다. `winmetrics.round_window_corners()`가 이미
같은 API를 쓰고 있으므로 함수 하나가 늘 뿐이다.

### 2.2 트레이 아이콘 고정은 즉시 반영되지 않는다

Windows 11은 아이콘 표시 여부를 `HKCU\Control Panel\NotifyIconSettings\<해시>`의
`IsPromoted` DWORD에 담는다. 세 가지를 시도했고 **셋 다 실패했다.**

| 시도 | 결과 |
|---|---|
| `IsPromoted=1` 쓰기 | 작업 표시줄에 안 나타남 |
| 값을 쓴 뒤 아이콘 재등록(앱 재시작) | 안 나타남 |
| `WM_SETTINGCHANGE` 7종 브로드캐스트 | 안 나타남 |

탐색기가 이 값을 시작할 때 읽고 그 뒤로는 자기 캐시를 쓴다. **탐색기 재시작은
하지 않는다** — 사용자의 열린 창을 전부 건드리는 짓이다. 따라서 이 기능은
**"다음 로그온부터 보이게 만드는" 기능**이다.

드래그로 꺼내는 것이 먹히는 이유는 탐색기 자신이 그 변경을 하기 때문이다.
레지스트리가 원인이 아니라 결과다.

### 2.3 Windows 10은 아이콘별 고정을 하지 않는다

Win10은 `HKCU\Software\Classes\Local Settings\...\TrayNotify`의 `IconStreams`
이진 blob에 담는다. 형식이 문서화돼 있지 않고 OS 버전마다 바뀔 수 있어
건드리지 않는다. 전역 스위치(`EnableAutoTray=0`)는 있지만 모든 앱에 적용되므로
우리가 조용히 켤 값이 아니다.

드래그로 꺼내는 것은 Win10에도 있고, **Win10에만 있는 아이콘별 설정 화면**
(설정 > 작업 표시줄 > 작업 표시줄에 표시할 아이콘 선택)도 있다. 안내는 그쪽을 가리킨다.

### 2.4 GDI는 글꼴 파일을 잠그지 않는다

`AddFontResourceW`로 올린 채 파일을 지웠고 성공했다. 폴더 통째 삭제도 됐다.
**PyInstaller 단일 파일 exe가 종료할 때 임시 폴더를 지우는 동작이 그대로
성공한다** — 종료 시 `RemoveFontResourceW`를 부를 필요가 없고 찌꺼기도 안 남는다.

Pretendard TTF 둘은 5.1MB, 현재 exe는 18.5MB다. 라이선스는 SIL OFL 1.1이고
"any software와 함께 번들·재배포할 수 있다"고 명시돼 있다. 조건은 저작권 표시와
라이선스 파일 동봉뿐이며 우리는 글꼴을 고치지 않는다.

### 2.5 링 안에 들어가는 글자 크기

3.1절의 링 치수에서 안쪽 지름은 40px이 나온다. 링 선과 글자 사이 4px을 남기면
쓸 수 있는 폭은 32px이다. Pretendard와 폴백(Segoe UI) 중 넓은 쪽으로 쟀다.

| 문구 | 들어가는 최대 크기 |
|---|---|
| `62` | 22px |
| `100` | 18px |
| `5:20` | 15px |

같은 크기로 `100`과 `5:20`을 둘 다 담으려면 15px이다. 그러면 평소 보는 숫자가
작아지므로 **문구마다 최대 크기를 따로 고른다.**

### 2.6 숫자의 세로 위치는 정확한 중앙이 없다

18px 숫자의 잉크는 13px(홀수), 링 안쪽은 40px(짝수, 2.5절)이다.
화면을 캡처해 픽셀을 센 결과:

| `create_text`의 y | 잉크 범위 | 위 여백 | 아래 여백 |
|---|---|---|---|
| 32 | 26~38 | 13 | 14 |
| 33 | 27~39 | 14 | 13 |

**반 픽셀은 위쪽으로 보낸다.** 아래로 보내면 처져 보인다(육안 확인).

이 값을 상수로 박지 않는다. 배율이 125%·150%가 되면 홀짝이 달라져 다시
틀어진다. `icon_render._centered_text`가 이미 하는 방식 — **그릴 때마다 잉크
상자를 재서 중앙을 맞추고 남는 반 픽셀을 위로 보내는 것** — 을 링 안 숫자에도 쓴다.

### 2.7 색 대비

트레이 아이콘은 채움 위에 흰 숫자를 얹는다. 고른 색을 그대로 쓰면 노란 구간이
읽히지 않는다.

| | 견본 그대로 | 어둡게 한 뒤 |
|---|---|---|
| 초록 | 2.61:1 | 3.19:1 |
| 노랑 | **1.71:1** | 2.69:1 |
| 빨강 | 3.35:1 | 4.12:1 |

1.71:1은 기존 `theme.py` 주석이 "사실상 읽히지 않는다"고 적어둔 구간이다.
트레이에 세 팔레트를 동시에 띄워 비교한 뒤 어두운 쪽으로 정했다.

**hex 값은 7장에 모아 두었다.** 여기는 대비 수치만 남긴다.

## 3. 오버레이

### 3.1 기본 모드 — 66 × 66

정사각형. 링 바깥 지름 50px(여백 8px), 두께 5px. **링 안에 숫자 하나만.**

- 사용량은 18px 굵게. `100`이면 그대로 18px(2.5절 표)
- 값이 없는 상태는 기호 하나만 — `icon_render`의 어휘를 그대로 쓴다
  - `!` 빨강 — 재로그인 필요
  - `?` 흰색 — 데이터 형식이 바뀜
  - `…` 흐린 회색 — 아직 값 없음
- **갱신이 늦어지면 링 채움을 지우고 흐린 `!` 하나만 그린다.** 낡은 숫자는
  없느니만 못하고, 숫자를 못 믿으면 링도 못 믿는다
- 값이 낡았지만 아직 주기 안이면 지금처럼 통째로 45% 흐리게

기준은 `poll_seconds + 60초`다. 분 반올림 경계에서 깜빡이지 않게 1분을 더한다.

`!`가 두 뜻을 갖게 되지만 밝기로 갈린다 — **기다리면 낫는 것은 흐리게, 사용자가
조치해야 하는 것은 또렷하게.** `icon_render`가 이미 쓰는 규칙이다.

갱신이 늦어지는 원인은 `poller.py`가 정한다. `credentials.py`가 토큰을 스스로
갱신하게 됐어도(커밋 `150ff57`) 이 목록은 그대로다 — 갱신에 실패해도 살아 있는
토큰이 있으면 조용히 그걸로 버티므로, 화면까지 오는 것은 네트워크 오류(백오프
최대 30분) · 429 · 401 경합 셋이다.

### 3.2 자세히 보기 모드 — 190 × 62

지금 모습 그대로다. 링 + 카운트다운 + 갱신 문구 두 줄. 창 폭 190px의 근거
(가장 긴 문구 181px + 여유 9px)도 그대로 살아 있고, **이제 그것은 자세히 모드
전용 근거다.**

### 3.3 조작

| | 기본 | 자세히 |
|---|---|---|
| 마우스 올림 | 변화 없음 | 우상단에 ⚙·✕ |
| 왼쪽 클릭 | 사용량 ↔ 남은 시간 | 아무 일 없음 |
| 드래그 | 이동 | 이동 |
| 오른쪽 클릭 | 메뉴 | 메뉴 |

- 단추는 **자리가 있는 쪽에만** 둔다. 66px 창의 구석에 넣으면 12px도 안 되어 못 누른다
- 자세히 모드의 **⚙는 설정창을 열고, ✕는 오버레이를 숨긴다.** ✕는 프로그램을
  끄지 않는다 — 트레이는 그대로 살아 있고 되돌리는 길은 트레이 메뉴다.
  풍선 알림도 띄우지 않는다. 우클릭 메뉴의 `설정…`·`오버레이 숨기기`와 같은
  동작이므로 단추는 지름길일 뿐이다
- 숨기기는 **누르는 즉시** 적용되고 `overlay_visible`도 그때 저장된다. 설정창의
  일괄 적용과 다른 이유는, 단추는 폼이 아니라 그 자체가 동작이기 때문이다
- 우클릭 메뉴는 양쪽 같다: `설정… / 자세히 보기 / ─ / 오버레이 숨기기`
- **드래그와 클릭은 3px로 가른다.** 누른 자리에서 3px 이상 움직이면 이동,
  그 안에서 떼면 클릭
- 자세히 모드에 좌클릭 전환이 없는 이유는 아래 줄에 이미 카운트다운이 있어서다
- **전환 상태는 저장하지 않는다.** 창 위치를 저장하지 않는 것과 같은 이유이고,
  다시 켜면 사용량으로 돌아온다

남은 시간 표기는 `5:20`(시:분)이다. 5시간 창이라 시는 한 자리이고, 자리를 채우는
`0`을 붙이지 않는다. `resets_at`이 없으면 전환해도 `—`가 나온다.

### 3.4 모드를 바꿀 때의 창 위치

창 크기가 바뀌므로 **오른쪽 아래 모서리를 고정**하고 크기를 바꾼다. 기본 위치가
작업 영역 오른쪽 아래이므로 그래야 제자리에 남는다.

**지금 코드에는 이런 보정이 없다.** 창 크기가 기동할 때 한 번 정해지고 그 뒤로
바뀌지 않기 때문이다. 예전에 `16d1eba`가 폭 변경에 대해 같은 보정(`_keep_right_edge`)을
넣은 적은 있으나, 위치 저장 기능을 통째로 되돌린 `62a2fa4`가 함께 지웠다.
새로 만드는 부분이다.

## 4. 설정창

네이티브 `Toplevel`. 크기 조절은 막는다. 대략 300 × 430.

제목 표시줄은 2.1절의 DWM 속성으로 어둡게 한다. 실패하면 제목 표시줄만
밝은 채로 뜬다 — 보기 나쁠 뿐 동작에는 지장이 없다.

### 4.1 담기는 것

```
☑ 오버레이 표시
    ☐ 자세히 보기
☑ 시작할 때 자동 실행
☐ 작업 표시줄에 트레이 아이콘 고정
    윈도우 제한으로 바로 반영되지 않습니다 — 다음 로그온부터 적용됩니다.
    지금 보려면 ∧를 눌러 아이콘을 작업 표시줄로 끌어다 놓으세요.
────────────────────────
조회 주기   [ 5분 ▾ ]        2 · 5 · 10 · 30분
노란색으로 바뀌는 사용률  ──●────  70%     50~100, 5단위
빨간색으로 바뀌는 사용률  ──────●  90%     50~100, 5단위
────────────────────────
닫으면 적용됩니다                    [ 닫기 ]
```

- **"자세히 보기"는 "오버레이 표시"의 하위 항목**이라 들여쓰고, 표시를 끄면 같이 흐려진다
- **조회 주기는 드롭다운**이다. 2분이 하한이고 그 아래는 호출 한도에 걸린다
  (`MIN_POLL_SECONDS`). 파일에 손으로 240초를 적어둔 경우 가장 가까운 5분이
  선택된 채로 열리고, 닫으면 그 값이 저장된다 — 드롭다운으로 바꾼 이상 피할 수 없다
- **슬라이더는 5단위**다. 세밀함보다 손으로 맞추기 쉬운 쪽을 골랐다.
  노란은 빨간보다 5%p 아래에서 멈추고 반대도 같다 — **서로 밀어내지 않고 그 자리에 선다.**
  불러올 때도 같은 규칙으로 보정한다(옛 파일에 모순된 값이 있으면 노란색이 영영 안 나온다)
- 트레이 고정 체크박스는 **Windows 10에서 비활성**이고 안내 문구가 바뀐다

### 4.2 직접 그리는 위젯

ttk 기본 위젯은 윈도우 기본 테마에서 색이 먹지 않는다. 체크박스·슬라이더·
드롭다운 셋을 캔버스에 직접 그린다. 링과 트레이 아이콘을 이미 PIL로 그리고
있으므로 이 코드베이스에 낯선 방식은 아니다.

- **체크박스** — 모서리를 둥글게 깎은 사각형. 꺼짐은 테두리만, 켜짐은 `GREEN`
  채움(7장)에 어두운 체크. **체크 표시는 글꼴 글리프(`✓`)가 아니라 끝이 둥근
  두꺼운 선 둘로 긋는다.** 글리프를 쓰면 글꼴마다 모양이 달라지고 획이 가늘다.
  캔버스 `create_line`의 `capstyle="round"`·`joinstyle="round"`로 그린다
- **슬라이더** — 손잡이는 원. 채운 부분은 그 기준의 색(`YELLOW`·`RED`)으로,
  빈 부분은 어두운 회색으로 칠한다. 무엇을 정하는 값인지 글자를 안 읽어도 보인다
- **드롭다운** — 펼친 목록의 **바깥 테두리를 단추의 바깥 테두리와 맞춘다.**
  폭을 따로 적지 않고 좌우를 테두리 두께만큼 물려서, 항목 글자가 길어져도 어긋나지 않는다

### 4.3 언제 적용되나

**닫을 때 한 번에.** 닫기 단추·제목줄 ✕·Esc가 모두 같은 일을 하고 취소는 없다.
값들이 다시 고르면 그만인 것들이라 취소가 벌어줄 게 없고, ✕만 취소로 두면
실수로 통째로 잃는다.

적용은 공유 `Config` 객체를 고치는 것으로 끝난다. 폴러·오버레이·트레이가
매 틱 다시 읽으므로 재시작 안내가 필요 없다.

- 색 기준 → 다음 다시 그리기(1초 이내)
- 조회 주기 → **다음 폴링 틱부터.** 자고 있는 대기를 깨우지 않는다. 깨우면
  API를 한 번 더 부르게 되고 그게 429의 원인이다
- 자동 실행·아이콘 고정 → **닫을 때 레지스트리에 쓴다.** 체크하는 순간이 아니다.
  **`Config`에는 저장하지 않는다** — 진짜 상태가 레지스트리에 있으므로, 창을 열 때
  거기서 읽어 체크박스를 그린다

### 4.4 함정 — 설정창을 열어둔 채 표시를 끄면

설정창이 떠 있는 동안 오버레이 우클릭 메뉴나 트레이로 표시를 끄면, 설정창의
체크박스는 켜진 옛 값 그대로다. 닫는 순간 그 값이 덮어써서 **오버레이가 도로
나타난다.** 표시 상태가 밖에서 바뀌면 열려 있는 설정창의 체크박스도 따라 갱신한다.

### 4.5 스레드

설정창은 두 곳에서 열린다 — 오버레이 우클릭(메인 스레드)과 트레이 메뉴(pystray
스레드). tkinter 창 조작은 메인 스레드 몫이므로 트레이 쪽은 위젯의 `after(0, ...)`로
넘긴다 — `overlay.py:194`의 `self._win.after(0, ...)`가 같은 방식이다. 이미 열려
있으면 새로 만들지 않고 앞으로 끌어온다.

## 5. 트레이 아이콘 고정

Windows 11에서만 동작한다.

- **찾는 법** — `NotifyIconSettings` 하위 키를 훑어 `ExecutablePath`가 우리
  실행 파일이고 `InitialTooltip`이 "Claude 사용량"으로 시작하는 것을 고른다.
  툴팁까지 보는 이유는 소스로 돌릴 때 `python.exe` 경로가 다른 파이썬 트레이 앱과
  겹칠 수 있어서다
- **시점** — 항목은 아이콘이 한 번 뜬 뒤에야 탐색기가 만든다. 첫 실행 자동
  시도는 별도 스레드에서 잠깐 기다렸다 쓰고, 끝내 못 찾으면 조용히 포기한다
- **첫 실행 1회 자동** — `config.json`이 없으면 한 번 써둔다. 이후로는 건드리지
  않는다. 나중에 직접 숨긴 사람과 싸우지 않기 위해서다
- **설정창 체크박스** — 언제든 켜고 끈다. 쓰고 나서 레지스트리를 다시 읽어
  실제 상태로 그린다. 안 그러면 화면이 거짓말을 한다
- 키가 없는 환경(Win10 등)에서는 체크박스가 비활성이고 아무것도 쓰지 않는다

## 6. 첫 실행 안내창

`config.json`이 없을 때 한 번 뜬다. **안내창을 띄우는 즉시 `config.json`을
기본값으로 저장한다** — 그러지 않으면 사용자가 아무 설정도 건드리지 않는 한
매 실행마다 뜬다.

작업 표시줄을 흉내 낸 도식(∧ 위치와 끄는 방향)을 도형으로 그린다. 스크린샷
파일을 끼워 넣지 않으므로 exe가 안 커지고 배율도 따라간다.

마지막 줄만 OS로 갈린다.

- **Win11** — "지금 안 하셔도 됩니다. 다음 로그온부터는 저절로 나옵니다."
  (첫 실행에 `IsPromoted=1`을 써두므로 참이다)
- **Win10** — "설정 > 작업 표시줄 > 작업 표시줄에 표시할 아이콘 선택에서 켜도 됩니다."
  (우리가 써둘 값이 없으므로 앞의 약속을 할 수 없다)

## 7. 색

고른 색 견본은 `#4ca45e` · `#f3a72e` · `#e3484a` 셋이다. **링과 채움은 그
견본에서 명도만 옮긴 것**이고 색상과 채도는 건드리지 않았다.

- **링** — 견본에서 지금 색 쪽으로 30% 밝힌 값. 어두운 창 위에 그리는 5px 선이라
  밝아야 보인다
- **채움** — 견본을 어둡게 한 값. 흰 숫자를 얹는 바탕이라 어두워야 읽힌다(2.7절)

## 8. 글꼴 번들

TTF 둘과 `OFL.txt`를 `claude_usage_overlay/fonts/`에 넣고 exe에 함께 묶는다.
기동할 때 그 경로로 `AddFontResourceW`를 부른다.

- **첫 실행부터 Pretendard다.** 기다림 0초, 네트워크 0, 실패 경로 0
- 계정 글꼴 폴더에도 레지스트리에도 쓰지 않는다
- 소스로 돌릴 때는 패키지 폴더, exe로 돌릴 때는 `sys._MEIPASS` 아래를 본다
- 번들 로드가 실패해도 `pick_font_family`가 Segoe UI로 떨어뜨린다

**사라지는 것** — `fetch_zip` · `pick_zip_asset` · `wanted_members` ·
`extract_to` · `register` · `install`, 트레이 메뉴의 "Pretendard 글꼴 설치",
README의 설치·삭제 안내. `font_install.py`는 40줄쯤으로 줄고 `activate()`만 남는다.

exe는 2.4절의 크기에서 3MB 안팎 커진다.

## 9. 트레이 메뉴와 config

```
오버레이 보이기 / 숨기기
지금 갱신
──────────────
설정…
시작할 때 자동 실행          ☑
──────────────
종료
```

"설정 파일 열기"는 설정창이 대신하므로 뺀다. "Pretendard 글꼴 설치"는 8장으로
사라진다. 자동 실행이 트레이와 설정창 양쪽에 있지만 둘 다 레지스트리를 읽어
그리므로 어긋나지 않는다.

`config.py`는 **`UI_OWNED` 개념이 없어진다.** 그 근거는 "나머지는 사용자가
메모장으로 고치는 값"이었는데, 이제 전부 GUI가 소유하므로 저장은 전체 쓰기로
단순해진다. 남는 위험은 프로그램이 켜진 채 파일을 손으로 고치는 경우뿐이고,
이제 그럴 이유가 없다.

새 필드는 `overlay_detailed: bool = False` 하나다. 기본값이 `false`인 쪽이
기본 모드와 일치해서 파일을 열어본 사람이 헷갈리지 않는다.

## 11. 실패 처리

- **DWM 어두운 제목 표시줄 실패** — 제목 표시줄만 밝게 뜬다. 조용히 넘어간다
- **레지스트리에 항목 없음** — 잠깐 기다렸다 다시 본다. 끝내 없으면 포기
- **키 자체가 없음(Win10)** — 체크박스 비활성, 아무것도 쓰지 않음
- **설정창에서 켰는데 실패** — 쓰고 나서 다시 읽어 실제 상태로 그린다
- **글꼴 번들 로드 실패** — Segoe UI로 떨어진다

## 12. 테스트

창을 띄우지 않고 재는 것들이다.

- 슬라이더 기하 — 값↔픽셀 왕복, 범위 밖 클램프, 5단위 스냅
- 노란·빨간이 서로를 넘지 않는 규칙, 불러올 때의 보정
- 초안 → `Config` 커밋 (순수 함수로 빼서)
- 조회 주기 드롭다운 — 목록에 없는 값(240초)이 가장 가까운 항목으로 붙는지
- **링 안 문구가 링 안에 들어가는지** — `62` · `100` · `5:20` · `0:27`,
  Pretendard와 폴백 둘 다로 재서 넓은 쪽. 2.5절 표가 근거다
- **잉크 중앙 정렬** — 배율 1.0 · 1.25 · 1.5에서 위·아래 여백 차이가 1px 이하이고
  남는 반 픽셀이 위로 가는지
- 3px 판정 — 2px 이동은 클릭, 4px 이동은 드래그
- 레지스트리 **항목 목록에서 우리 것 고르기** — 실제 접근은 얇은 껍데기로 분리.
  `python.exe` 경로가 겹치는 경우가 여기 들어간다
- 기존 `test_config.py`의 `UI_OWNED` 관련 테스트 갱신
- 기존 `test_overlay_layout.py`는 자세히 모드 근거로 남기고, 기본 모드 몫을 추가

## 14. 미해결

- **`IsPromoted`가 다음 로그온에 실제로 반영되는지 확인하지 않았다.** 값을 써두고
  로그오프·로그인을 해봐야 안다. 구현 첫 단계에서 확인하고, 안 되면 이 기능을
  빼고 안내창만 남긴다
- **배율 125%·150%에서 링 안 숫자의 중앙 정렬**을 실측하지 않았다. 100%에서만
  쟀다. 잉크를 매번 재는 방식이므로 맞을 것으로 보지만 확인이 필요하다
- 설정창 실제 크기(300 × 430)는 한국어 문구 길이를 눈대중한 값이다. 만들면서
  가장 긴 문구로 역산한다
